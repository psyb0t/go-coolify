# go-coolify

Unofficial Go client for the Coolify Public API, generated from the OpenAPI document Coolify publishes. If you only want to use the client from an agent, read [.agents/skills/go-coolify/SKILL.md](.agents/skills/go-coolify/SKILL.md) instead; this file is about changing the code.

## Architecture

One generated package, `coolify`, at the module root, driven by `gen.go`:

`scripts/fetch-spec.sh` downloads `https://raw.githubusercontent.com/coollabsio/coolify/main/openapi.json` to `api/openapi.json` → `scripts/patch-spec.sh` writes `api/openapi.patched.json` → oapi-codegen with `config.yaml` → `client.gen.go`.

The patch converts nullable type arrays into a single type plus `nullable: true`, and defines the missing `components.responses.403` with the description `Forbidden.`. It does not invent a body schema.

Seven identical log-line query unions become references to a named `LogTailLines` component, so the generated union has exported helpers. The integer and `all` alternatives stay intact.

## Stack

- Go 1.26.10.
- oapi-codegen, pinned as a `tool` dependency in `go.mod`.
- Runtime: `github.com/oapi-codegen/runtime`.

## Layout

- `gen.go`, `config.yaml`, `client.gen.go`: the package.
- `client_test.go`, `example_test.go`: tests, including the README example.
- `scripts/`: spec download, spec patches, lint and security scan scripts.
- `api/`: the downloaded spec, gitignored.
- `vendor/`: committed, regenerated by `make dep`.

## Dev workflow

Everything runs in the `Dockerfile.dev` image. You need Docker and Make.

```bash
make dep       # go mod tidy + go mod vendor
make generate  # download the spec and regenerate
make lint      # shellcheck, shfmt, go fix, golangci-lint
make test      # go test -race
make sec       # gitleaks, govulncheck, semgrep
```

## Project-specific landmines

- OpenAPI 3.1 nullable type arrays need conversion before oapi-codegen can load the document.
- The spec references `components.responses.403` without defining it. The patch supplies a description only; inspect `Body` for those responses.
- Preserve the `number` to `float64` mapping in `config.yaml`.
- Explicit `format: float` fields retain the generator's `float32` mapping. The `float64` mapping applies to unformatted numbers.
- Generated comments retain upstream descriptions. Change the source patch if an upstream description needs correction; never edit generated prose directly.
- Log-line query values use the generated `LogTailLines` union helpers. An anonymous inline union would hide those helpers from callers.
- The user must supply the instance base URL, including `/api/v1`. Generated endpoint paths do not include that prefix.
- The `bearerAuth` scheme needs an `Authorization: Bearer <token>` request editor. The generated client does not add auth or read environment variables.
- Method names come from the spec's operation IDs. Verify names in generated code when changing the README or skill.
- `make generate` always downloads the current spec, so it can change the client even when nothing here changed. Review the generated diff before committing it.
- `.github/workflows/regen.yml` regenerates the client every day and releases the result. When the checks fail, Claude edits the repository to fix them, but a fix may not touch the paths listed under `fix_protected_paths` in that workflow: the workflows, the Makefile, `AGENTS.md`, `.agents/rules/`, the lint, security and spec download scripts and their configs. A problem that needs a change there fails the run and needs a manual fix.
